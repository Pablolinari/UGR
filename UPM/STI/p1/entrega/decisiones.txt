1. MATERIAL CLAVE
==================================================
¿Qué claves genera o utiliza la solución? ¿Por qué eligió su longitud y formato?

Respuesta (máximo 50 palabras):

Utilizo dos claves distintas, una para cifrar y otra para integridad , las claves las introduce el usuario y son las mismas para 
todos los archivos ya que considero un entorno que no necesita seguridad tan alta y es más cómodo para el usuario. 

La clave se pasa por una función de derivación, para hacerla más resistente contra ataques.


==================================================
2. CONFIDENCIALIDAD E INTEGRIDAD
==================================================
¿Qué primitivas criptográficas utiliza y por qué?

Respuesta (máximo 50 palabras):

Para el cifrado uso AES-128 que es el estándar actual para cifrar, con la clave derivada mediante PBKDF2  para
resistir ataques de fuerza bruta sobre la contraseña. Para la integridad uso SHA256 con una
clave distinta, verificándolo antes de desencriptar para detectar si la información ha sido manipulada.


==================================================
3. ARCHIVOS GENERADOS
==================================================
¿Qué archivos genera la solución?

Respuesta (máximo 50 palabras):

La solución genera archivos temporales (que no ve el usuario) y el resultado son los mismos archivos 
que había en el directorio pero cifrados y acompañados de un archivo con el mismo nombre y con extensión .hmac
donde se guarda el hash que garantiza integridad.


==================================================
4. RECUPERACIÓN Y VERIFICACIÓN
==================================================
¿Qué verificaciones realiza antes de recuperar
la información?

Respuesta (máximo 50 palabras):

Genero un hash del archivo antes de desencriptarlo y compruebo que coincide con 
el hash que he guardado en el archivo con el mismo nombre y extensión .hmac

Si se garantiza la integridad lo desencripto , si no imprimo un mensaje en la pantalla avisando de la falta de integridad.
y no lo desencripto para mantener el sistema seguro.


==================================================
5. USO DEL PROGRAMA
==================================================
¿Cómo se gestiona el uso que una persona usuaria hace?

Respuesta (máximo 50 palabras):

La persona ejecuta los scripts y debe introducir dos contraseñas
una para encriptar y la otra para garantizar integridad. 

Una vez ejecutado proteger.sh , el proceso es el mismo pero con 
recuperar.sh , esta vez , el sistema comprobará si se mantiene 
la integridad y en este caso se desencriptarán, si no se avisará al 
usuario.



==================================================
6. SISTEMA DE ARCHIVOS Y ENTORNO
==================================================
¿Cómo se gestiona la interacción del programa con el entorno de ejecución?

Respuesta (máximo 50 palabras):

Los scripts operan sobre el directorio actual ($PWD), recorriendo sus archivos y excluyéndose a sí mismos y a los .hmac. Usan un archivo temporal .bin que sustituye al original con mv, y las contraseñas se leen por pantalla sin ocultarse (sin la opción -s de read).

==================================================
¿Qué dimensión de la seguridad no proporciona su
solución aunque funcione correctamente?

Respuesta (máximo 50 palabras):

No contempla el uso de contraseñas individuales para cada archivo.
